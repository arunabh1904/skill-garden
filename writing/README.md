# Writing skills

Begin with [writing-style](writing-style/SKILL.md). Add one primary category skill per artifact when its reading job calls for one. An explicit category wins; otherwise use this map.

| Reader's job | Primary skill | Boundary |
| --- | --- | --- |
| Understand a short message, caption, blurb, or ordinary summary | [writing-style](writing-style/SKILL.md) alone | No article template or publishing workflow |
| Follow an argument, reflection, explanation, or research synthesis | [write-blog-post](write-blog-post/SKILL.md) | Short and long form; may center on one paper or many |
| Reconstruct one research paper for later technical decisions | [write-paper-note](write-paper-note/SKILL.md) | Arxiv Notes; compact evidence and mechanism, with the site note shell |
| Recall or reconstruct material from lectures, books, documentation, or courses | [write-revision-notes](write-revision-notes/SKILL.md) | Retrieval order, derivations, examples, or requested recall cards |
| Practice implementing and explaining a coding solution | [write-code-practice-problem](write-code-practice-problem/SKILL.md) | Problem contract, hints, runnable code, and solution explanation |

Length does not choose the category. A 400-word argument about a paper can be Blog; a longer, technically complete reconstruction can still be an Arxiv Note. Summarizing one lecture for recall belongs in Revision Notes; using it to develop an independent argument belongs in Blog. Ordinary summaries outside the site need only the base style unless a specific format is requested.

## Rule Ownership

| Concern | Canonical home |
| --- | --- |
| Editing scope, voice, evidence, paragraph continuity, prose audit | [writing-style](writing-style/SKILL.md) and its prose system |
| Blog reading modes, depth, title and heading judgment | [write-blog-post](write-blog-post/SKILL.md) |
| Technical figure and animation design for Blog | [Blog visual reference](write-blog-post/references/technical-visuals.md), loaded when needed |
| Arxiv Note shell, taxonomy, takeaways, images and captions | [paper-note-format](write-paper-note/references/paper-note-format.md) |
| Field-wide chronology review | [write-paper-note](write-paper-note/SKILL.md), only for that review scope |
| Retrieval structure and coding exercise contracts | The corresponding category skill |
| Narration extraction, voice profile, export, and artifact quality | [add-blog-voice](add-blog-voice/SKILL.md) |
| Site integration, validation, queue routing, PRs, deployment and cleanup | [publish-website-writing](publish-website-writing/SKILL.md) |

The user's requested scope governs every layer. Category rules adapt format and depth; they do not override evidence standards or authorize broader edits. Skill instructions describe how to perform an authorized task, not permission to start adjacent work.

Drafting and local editing stop at that stage unless release is requested or already established in the task. A Blog release includes follow-up narration under the publishing workflow, except when the user chooses text-only publication or defers audio. A prose-only listening check does not generate audio. A named paper does not require Paper Radar access; queue instructions apply to queue requests.
